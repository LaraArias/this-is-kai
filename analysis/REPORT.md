# What moves the tokens-per-second score

Generated by `analysis/analyze.py` from `data/runs.csv` and `data/calls.csv`. Do not edit by hand.

Every rate here is server-reported (completion tokens over completion time) for Kimi K3.1 Pro on Cerebras through OpenClaw. These runs were not controlled experiments: prompts, stores, queue load and time of day changed between them. The tables show where speed differs. They do not show why.

## 1. What is in the data

45 agent runs and 250 model calls, all Kimi K3.1 Pro on Cerebras through OpenClaw. `browsing` runs let the agent find products by opening store pages; `catalog` runs name one store's live search endpoint in the prompt.

## 6. How much of the spread these labels describe

Ordinary least squares of per-call rate on four labels. It describes this sample; it is not a causal estimate.

|                    |   coefficient (tokens/s) |
|:-------------------|-------------------------:|
| intercept          |                    940.8 |
| log(output tokens) |                    -67.2 |
| is a tool call     |                    158.5 |
| is the first call  |                   -271.9 |
| is a catalog run   |                    317.7 |

R² = 0.23: the labels account for about 23% of the variance between calls. The rest is not explained by anything recorded here.
